1. About this guide

This guide tells you how to install and use GeoFunctions. It also tells you how to build, test and release the library.

Each figure with code is the output of that code. The script guide/make_guide.py runs the code on Spark when it builds this page. If the code stops working, the build stops. The script reads the function reference from the source code.

Text conventions

  • A procedure has numbered steps. Each step has one action. Do the steps in the given sequence.
  • A CAUTION tells you about a risk of data loss or a failed job.
  • A NOTE gives more information.
  • Code that you can use as it is has a gray background. Replace text in angle brackets, for example <path-to>.
  • A blue line on the left marks the result of the code above it.

2. Library overview

GeoFunctions adds spatial functions to Spark. You use them from the PySpark DataFrame API or from Spark SQL. The library has {{n_py}} public Python functions and {{n_sql}} SQL names.

The library has two components:

  • A Python wheel. It contains one file, geofunctions/__init__.py.
  • A shaded Scala jar. It contains the Spark expressions and the Esri Geometry API.
{{fig:architecture}}

How a function call works

  1. A Python wrapper, for example st_buffer, calls the GeoFunctions object in the jar through py4j.
  2. The object makes a Catalyst expression and gives it back as a Column.
  3. Spark runs the expression on the executors. No Python worker is necessary for this.

Each expression has two execution paths: an interpreted eval and generated code. Both paths give the same result.

Python only functions

Some functions do not have an expression of their own:

  • *_explode functions apply explode() to a function that returns an array.
  • join_qr and knn_join start processors in the jar.
  • qr_cells calculates on the driver. It does not start a Spark job.
  • pairwise_dissolve runs a loop of Spark jobs.
  • to_spark, to_feature_class and to_feature_table move data to and from ArcGIS.

The import of geofunctions also adds methods to DataFrame: pairwise_dissolve, join_qr, knn_join, to_feature_table and to_feature_class. Thus df.join_qr(other, 1.0) and join_qr(df, other, 1.0) are the same.

Arguments

  • A string argument of a column function is a column name, not a value. To give a value, use lit().
  • Many functions have a default column name, for example "geom". See the function reference.
  • Most functions give an alias to the result, for example geom, area or text.

4. Install the library

4.1 Install on ArcGIS Pro

Do this procedure in the ArcGIS Python Command Prompt.

  1. Download geofunctions-{{version}}.zip.
  2. Extract the zip file to a folder.
  3. Go to your home folder:
    cd %HOMEPATH%
  4. Make a new conda environment:
    conda create -n geofunctions --yes --clone arcgispro-py3
  5. Make the new environment active:
    proswap geofunctions
  6. Get the spark-esri package:
    git clone https://github.com/mraad/spark-esri.git
  7. Go to the package folder:
    cd spark-esri
  8. Install the package:
    pip install .
  9. Install the wheel from the zip file:
    pip install --no-deps <path-to>/geofunctions-{{version}}-py3-none-any.whl

On ArcGIS Pro 3.7, also do the procedure in section 4.2.

4.2 Replace Spark on ArcGIS Pro 3.7

Spark 4.1.1 on Windows with Python 3.12 or higher stops each Python worker (SPARK-53759, Esri KB 000039267). Spark 4.1.2 has the correction. This failure has an effect on createDataFrame from a Python list, rdd.map(), @udf and @pandas_udf. The GeoFunctions functions and Spark SQL do not use a Python worker. Thus they work without this procedure.

  1. Install PySpark 4.1.3:
    pip install pyspark==4.1.3
  2. Set the Spark home:
    set SPARK_HOME=%CONDA_PREFIX%\Lib\site-packages\pyspark
  3. Restart the notebook kernel.
NOTEspark_esri reads SPARK_HOME when you import it. A change after the import has no effect until the restart.

4.3 Install without ArcGIS Pro

  1. Install PySpark 3.5.9 or 4.3.0:
    pip install pyspark==3.5.9
  2. Install the wheel:
    pip install --no-deps <path-to>/geofunctions-{{version}}-py3-none-any.whl
  3. Download the jar that matches PySpark. See section 3.
  4. Remove SPARK_HOME from your environment. On macOS and Linux, use this command:
    unset SPARK_HOME
CAUTIONIf SPARK_HOME points to a different Spark, PySpark uses the jars of that Spark. The session or the first function call then stops. The error is 'JavaPackage' object is not callable or ClassNotFoundException: scala.collection.SeqOps.

4.4 Install optional packages

The notebooks use these packages. The library does not need them:

pip install geopandas mapclassify folium xyzservices duckdb fastparquet

The arcpy bridge needs pyarrow and pandas. ArcGIS Pro has both. The other functions do not need them.

5.1 Start a session in ArcGIS Pro

  1. Set the path of the jar.
  2. Call spark_start.
  3. Import geofunctions.
import spark_esri

jar = r"<path-to>\geofunctions-{{version}}-2.13.jar"
spark = spark_esri.spark_start(config={
    "spark.jars": jar,
    "spark.driver.extraClassPath": jar,
    "spark.driver.memory": "4G",
    "spark.executor.memory": "4G",
})

import geofunctions as S

To stop the session, call spark_esri.spark_stop().

5.2 Start a session without ArcGIS Pro

import os
from pyspark.sql import SparkSession

jar = os.path.expanduser("~/geofunctions-{{version}}.jar")
spark = SparkSession.builder.config("spark.jars", jar).getOrCreate()

from geofunctions import st_point, st_astext
NOTEPython and Spark do not expand ~. Use os.path.expanduser. If you do not, Spark does not find the jar.

5.3 Use SQL

The DataFrame API does not need registration. SQL names need it.

  1. Call st_register_functions() once in each session.
  2. Use the names in spark.sql.
from geofunctions import st_register_functions

st_register_functions()
spark.sql("SELECT ST_ASTEXT(ST_POINT(1.0, 2.0)) AS text, ST_AREA(ST_RECT(0.0, 0.0, 2.0, 3.0)) AS area").show()
text = POINT (1 2), area = 6.0

5.4 Set the session by hand

Use spark.jars if possible. If you set PYSPARK_SUBMIT_ARGS, obey these rules:

  • Separate the items of --driver-class-path with os.pathsep.
  • Separate the items of --jars with commas.
  • On Windows, use forward slashes (Path(p).as_posix()) or shlex.quote. PySpark removes backslashes from this variable.
  • Set PYSPARK_PYTHON to your interpreter.

6. Data rules

6.1 Geometry is WKB

A geometry column is a binary column that holds WKB. Most functions read and write WKB. To read a geometry, use st_astext or st_asgeojson. To make a geometry from text, use st_fromtext.

WKB has no envelope type. An envelope that you write as WKB becomes a polygon.

6.2 Null input gives null output

A function returns null if an argument is null. There is one exception: st_isempty returns true for a null geometry. A *_explode function gives no rows for null input. join_qr excludes rows with a null QR or a null geometry.

6.3 Spatial reference

Functions with a wkid argument use it to make the spatial reference. The value -1 means planar calculation. Numbers such as 4326, 3857 and 102008, and the forms with the prefix EPSG:, are all accepted. Default values are not the same for all functions. Examine the function reference.

6.4 Use the data in Python

toPandas() gives WKB as bytearray. Shapely 2.1 accepts only bytes. Change the type first:

pdf = df.toPandas()
gdf = gp.GeoSeries.from_wkb(pdf.geometry.map(bytes, na_action="ignore"))

8. Spatial predicates

A predicate compares two geometries and returns true or false. In SQL, the six predicates ST_INTERSECTS, ST_CONTAINS, ST_WITHIN, ST_TOUCHES, ST_OVERLAPS and ST_DISJOINT take two or three arguments. If you do not give wkid, it is '-1'.

{{fig:predicates}}

8.1 Repeated geometry

The six predicates and st_dwithin keep the last 4 parsed geometries of each argument. If a row has the same bytes, the function uses the parsed geometry again. This has effect on:

  • A literal, for example lit(bytes(wkb)).
  • A SQL scalar subquery.
  • A join that repeats a small number of geometries.
county = zone.where("z_name = 'Coconino County'").select("z_boundary").first()[0]
trip.where(st_intersects("t_pickuploc", lit(bytes(county)))).count()

On SpatialBench SF1, this query compares 6 million points with one polygon of 10,583 vertices. The time changed from approximately 66 s to 0.2–0.4 s.

8.2 Far-apart pairs

The six predicates compare the envelopes first. If the envelopes are apart, the function gives the result without the exact test. Thus you do not need a st_intersects_box filter before these predicates.

8.3 Many points and one large polygon

Spark gives each row its own copy of a binary value. Thus st_within(point, polygon) copies and parses a large polygon for each candidate. st_within_mask reads the polygon one time.

  1. Group the candidate points of each polygon with collect_list.
  2. Call st_within_mask one time per polygon.
  3. Explode the result with arrays_zip.
cand.groupBy("zonekey").agg(collect_list(struct("pt", "dur")).alias("ps")) \
    .join(zones, "zonekey") \
    .select("zonekey", "ps", st_within_mask(col("ps.pt"), "boundary").alias("mask")) \
    .select("zonekey", explode(arrays_zip("ps", "mask")).alias("e")).where("e.mask")

On SpatialBench Q10 at SF1, the time changed from 20 s to 3.7 s.

10. The QR grid

10.1 Cells and keys

The QR grid divides the plane into squares. The side of each square is cell. The grid has no limit and includes negative numbers. Each cell has a number q and a number r. One bigint holds the two numbers. Spark can use this key in an equi-join and in a Parquet filter.

{{fig:qr_grid}}

Related functions are st_lontoq, st_lattor, st_qtox, st_rtoy, qr_fromgeom and qr_contains_geom.

10.2 The dist argument

Cell (q, r) spans [q*cell - dist, (q+1)*cell + dist] on each axis. Adjacent cells overlap by 2 * dist. A geometry near an edge is thus in more than one cell. A QR equi-join can then find pairs on the two sides of an edge.

{{fig:qr_dist}}
NOTESet dist to the largest search distance that you need.

10.3 Read the cells of a geometry

{{fig:qr_family}}

The *_explode functions give one row per array item. These functions use the envelope of the geometry to find the cells. Thus qr_list can include cells that the geometry does not touch.

All these functions use the same cells for the same cell and dist. cell must be finite and positive. dist must be finite and not negative. Each key must fit a signed 32-bit q and r, and the count must fit a Spark array. If not, the function stops with an error before it allocates memory. An empty geometry gives an empty array, or 0 from qr_count.

10.4 Clip a segment

clip_line takes one segment as an array of four doubles, [x1, y1, x2, y2]. It does not take a polyline. To clip a polyline, make one row for each segment first.

{{fig:clip}}

clip_line_dist adds dist. With dist = 0, the lengths add up to the segment length. With dist > 0 the cells overlap, and the sum is larger. st_clipline and st_cliplinedist are aliases.

10.5 Read part of a sorted table

qr_cells gives the same values as qr_list for one geometry. It calculates on the driver. Use it to read part of a Parquet table that you wrote sorted by a QR column.

  1. Write the table sorted by the QR column.
  2. Set the threshold above the number of cells.
  3. Get the cells of the area.
  4. Filter on the cells.
  5. Keep the exact predicate.
spark.conf.set("spark.sql.parquet.pushdown.inFilterThreshold", "1000000")
cells = qr_cells("POINT (-111.761 34.8697)", 0.5, 0.45)
trips.where(col("t_pickup_qr").isin(cells)).where(st_dwithin("t_pickuploc", center, 0.45))
CAUTIONAbove the threshold, Spark pushes only the minimum and the maximum of the list. That range contains all the rows between them. Hundreds of cells spread over the world can cost more than they save.

This method makes SpatialBench Q1 and Q3 2 to 3 times faster.

11. Spatial joins

11.1 How join_qr finds pairs

  1. The function adds a qr column to each side if the column is not there. It uses qr_envp_explode.
  2. Rows meet only when they have the same cell.
  3. qr_intersect keeps a pair only in its canonical cell. This is the cell that holds the lower-left corner of the overlap of the two envelopes.
  4. The exact oper test runs.

Step 3 makes sure that a pair that shares many cells comes back one time.

{{fig:join}}

11.2 Select an execution path

{{fig:join_paths}}

On SpatialBench Q4 at SF1 (1000 points, 156,095 polygons), the default path took 1.9–44 s, because it shuffles 1.4 GB of polygons. The broadcast path took 0.42 s.

11.3 Arguments of join_qr

11.4 Select the cell size

  • A small cell copies large polygons into many rows.
  • A large cell puts more geometries in each cell, so more exact tests run.
  • For the default path, use a cell near the size of a typical geometry on the large side.
  • For the broadcast path, the cell has a small effect (0.42–0.57 s for 2° to 45° on Q4).

The script benchmarks/optimize_qr_join.py selects a cell size from your data.

11.5 Nearest neighbors

knn_join(lhs, rhs, k) gives each lhs row its k nearest rhs rows, by planar distance.

{{fig:knn}}
  • The function copies rhs to each task. Thus rhs must be small: tens of thousands of rows.
  • A null lhs geometry gives no rows.
  • If rhs has fewer than k rows, each rhs row comes back.
  • At equal distance, the rhs row that comes first stays.

The search is exact. An R-tree finds the k nearest envelopes. Their exact distances give a radius. Each entry in that radius then gets an exact distance. The R-tree stores floats, so each box is rounded outward and the radius gets more length. The tree thus does not drop a true neighbor.

12. Parts and dissolve

12.1 Split a polygon into parts

st_dump returns an array of parts. st_dump_explode gives one row per part. A part keeps its holes. An island in a hole is a part of its own. The function uses containment to group the rings, not the sequence in the file. Thus the result is correct when the file has a hole before its exterior ring.

{{fig:dump}}

12.2 Dissolve polygons

pairwise_dissolve merges polygons that touch or overlap. It does this over a series of larger cells.

  1. The function clips each polygon to the cells of the current size, with a margin.
  2. It merges the clipped polygons in each cell.
  3. It writes a merged part if the envelope of the part fits in one cell, and that cell is the home cell of the part. The home cell holds the lower-left corner of the envelope.
  4. It sends the other parts to the next round. The cell size is then cell * cell_mul.
  5. After breaker rounds, it merges the remaining parts in one pass with no grid.
{{fig:dissolve}}
  • Each merged polygon comes back one time and keeps its holes.
  • The result has one column: the geometry.
  • The margin is the larger of dist and cell * 1e-6. With no margin, a part cut on the edge of its cell seems complete, and the polygon stays split.
  • The function uses localCheckpoint() on each intermediate result. This keeps the query plan small.
CAUTIONThe value 0 is a cell edge at each cell size. A polygon across x = 0 or y = 0 can never finish in a cell, so it goes to the last pass. One task does the last pass. With a small breaker on large data, that task can run out of memory. Keep the default breaker of 10 for large data.
NOTEThe defaults are cell=100000.0, dist=100.0, wkid=3857, cell_mul=10.0. These values are for meters. Set them for other units.

{{fig:gdb}}

13.2 Select the function

Pointgdb_point: one function for all layouts. A NaN x or y gives an empty point.

13.3 The SHAPE column

  • A point layer gives a struct with named fields: x, y[, z][, m].
  • Other layers give struct<xmin, ymin, xmax, ymax, parts, coords>. parts holds the number of vertices in each path or ring. A multipoint has one item: the point count. coords holds all values in sequence.
  • The values per vertex are coords.length / sum(parts).
  • Spark column names ignore case. Thus "SHAPE" and "Shape" are the same.

13.4 Read a Shapefile

df = spark.read.format("shp").option("path", "<folder-or-file>").load()
df.select(st_astext("shape")).show(1)

The shape column is WKB. You do not need a decode function.

14. The arcpy bridge

Three functions move data between Spark and ArcGIS. They need ArcGIS Pro, because they import arcpy. The import is in each function. Thus import geofunctions works without ArcGIS Pro.

{{fig:arcpy}}

14.1 Write a feature class

  1. Make a DataFrame with one WKB geometry column.
  2. Make sure that all rows have the same geometry type.
  3. Call to_feature_class.
df.to_feature_class("my_fc", geom="geom", sp_ref=4326, workspace="scratch")
ArgumentValues
geomThe geometry column. The default is geom.
sp_refA wkid. The default is 3857. None or a value that is not positive uses the spatial reference of the active map. This needs an open ArcGIS Pro project.
workspace"scratch" (default), "memory" or the path of a geodatabase.

14.2 Write a table

df.to_feature_table("my_table", workspace="scratch")

14.3 Read a feature class

df = to_spark("my_fc")                                   # OBJECTID and SHAPE only
df = to_spark("my_fc", fields="*")                       # all fields
df = to_spark("my_fc", fields=["OBJECTID", "SHAPE", "Name"], where_clause="Population > 100000")

The geometry column keeps the name that it has in the feature class. The result keeps Z and M. An empty feature class gives an empty DataFrame.

15. H3

H3 is the only hexagonal index in the library. The H3 jar is not in the shaded jar, and ArcGIS Pro does not have it. You must add it.

  1. Find the version under com.uber:h3 in pom.xml.
  2. Download the jar:
    curl -O "https://repo1.maven.org/maven2/com/uber/h3/${H3_VER}/h3-${H3_VER}.jar"
  3. Add it to spark.jars with the GeoFunctions jar:
    spark = SparkSession.builder.config("spark.jars", f"{gf_jar},{h3_jar}").getOrCreate()
{{fig:h3}}
CAUTIONA driver-only classpath works with local and fails on other masters. If the jar is missing, the session starts, and the first H3 call stops with NoClassDefFoundError: com/uber/h3core/H3Core. Use spark.jars. It covers the driver and the executors.

16. Performance

17.6 Add a function

  1. Add STFoo.scala with an expression and a companion object.
  2. Add the function to Registry.registerFunctions().
  3. Add def stFoo(...) to GeoFunctions.scala.
  4. Add def st_foo(...) to __init__.py, with a reST docstring.
  5. Add the function to functions.md and the README list.
  6. Run python guide/make_guide.py.

The expression must return null for null input in eval and in generated code. NullPropagationSpec finds each new expression and tests this.

19. Known limits

  • The SQL names are not all complete or the same as the Python names:
    • QR_ENVPGROM is a spelling error of QR_ENVPGEOM. It stays so that existing callers continue to work.
    • qr_geom is QR_CLIP in SQL.
    • ST_CLIPLINE and ST_CLIPLINEDIST are not registered.
    • There is no SQL name for the change from y to r. ST_RTOY and ST_XTOQ are available.
  • join_qr does not support disjoint. Its broadcast path does not support crosses or equals.
  • knn_join uses planar distance. It copies rhs to each task.
  • pairwise_dissolve does the last pass in one task.
  • xyz and xym layers cannot be told apart by the value count. See section 13.2.
  • ArcGIS Pro 3.6 does not work.
  • A Spark 4.1 incompatibility in a function that the tests do not call shows only at run time. The 2.13 jar is built for Spark 4.3. The tests on Spark 4.1 do not cover each function.
